# 实验设计与证据链

## 1. 预注册式实验卡

每个重要实验先写：

| Field | Content |
|---|---|
| Question | 要回答什么 |
| Hypothesis | 预期及理由 |
| Inputs | 数据和选择规则 |
| Independent variables | 主动改变什么 |
| Dependent variables | 测量什么 |
| Controls | 固定什么 |
| Correctness gate | 什么情况下停止 |
| Repetitions | 预热、pilot、formal次数 |
| Statistics | mean/median/IQR/SD等 |
| Raw output | 保存位置和schema |
| Expected limitation | 能说明什么、不能说明什么 |

## 2. 正确性先于计时

性能实验前必须验证：

- 所有算法结果正确；
- 多个实现输出一致；
- 排序或变换未丢失/复制记录；
- 查询路径和分量合法；
- 输入副本、I/O、验证、输出和绘图不进入不应计时的区域。

若正确性失败，正式计时无效。

## 3. 计时实验

在 JVM、解释器或有 JIT/GC 的环境中：

- 使用预热；
- 做 pilot 检查漂移和分辨率；
- 正式实验重复多次；
- 保留所有 raw values；
- 明确使用的集中趋势和离散指标；
- 使用同一机器、运行时和条件；
- 轮换算法顺序，避免固定顺序偏差；
- 不把不同平台的 wall-clock 值混在同一正式比较中。

操作计数、访问节点、检查边数、写入次数、递归深度等平台无关指标可以补充 wall-clock，但必须明确定义计数口径。

## 4. 受控实验与观察性比较

不同数据集之间的差异通常同时包含规模、分布和顺序，属于观察性证据。若要声称某个因素造成结果，尽量对同一记录集合只改变一个变量。

报告中区分：observed result、controlled result、theoretical expectation、inference和unverified claim。

## 5. Scaling与复杂度

真实 scaling 数据用于说明当前范围内的增长趋势，Big-O用于理论外推。小规模实验不能证明渐近复杂度。

复杂度推导应连接实际实现：

1. 定义变量；
2. 指出主循环、递归或数据结构操作；
3. 计算执行次数或访问上界；
4. 合并并化简；
5. 区分 best/average/worst；
6. 区分输入存储和 auxiliary space；
7. 说明实现选择如何影响边界。

## 6. Raw-to-summary验证

汇总文件不是独立真相。表图生成前应从 raw data 重新计算关键统计，并与 summary 比较。

验证行数和分组、缺失或重复trial、单位、统计口径、rounding tolerance、异常值保留和版本一致性。

## 7. 图表选择

- 精确 required output：表格；
- 分布和离群值：boxplot；
- 随规模变化：line chart；
- 多维相对比较：适量 heatmap；
- 组成分布：bar chart通常优于饼图；
- 路径或拓扑：graph/tree/layer visual；
- 不制作重复表达相同结论的装饰图。

每张图记录：source artifact and rows、metric and unit、transformation、question supported、direct conclusion、limitations和使用位置。

## 8. 失败实验处理

- 记录失败条件；
- 判断是实现错误、协议错误还是环境噪声；
- 修复原因，不美化结果；
- 若改变协议，记录前后差异和理由；
- 新旧运行不能混合；
- 未通过 pilot 时不得继续正式结论。

## 9. 先研究论文和课程方法

在设计重要实验前，先读取课程指定材料，并检索原始论文、正式标准和官方文档。建立方法矩阵：

| Source | Question | Method | Controls | Metrics | Validation | Limitation | Adopt/adapt/reject |
|---|---|---|---|---|---|---|---|

借鉴的是研究设计、证明过程、指标和论证方式，不是复制其结论。每个采用的方法说明如何适配当前数据、平台和任务。

优先选择与任务高度相关、经过同行评审且在本领域具有公认权威性的来源。期刊论文应从当前权威来源核验影响因子、JCR分区或学科地位，优先高影响力/Q1来源；计算机科学顶级会议通常没有期刊影响因子，应核验CCF、CORE、领域公认等级、录用标准或课程指定地位。记录指标的年份和来源，不为会议虚构影响因子，也不只凭指标替代方法相关性判断。

引用数量采用内部质量目标：教师最低要求为 `N` 时不少于 `N+4` 个高相关来源；教师未规定时不少于 12 个高相关来源。官方限制优先，相关性和真实性优先于数量。

## 10. 加分机会实验

基线评分后检查下列工作是否有官方评分价值：

- 控制变量对照；
- 关键组件消融；
- 边界、异常、压力或鲁棒性测试；
- 不同算法/设计方案比较；
- 敏感性分析；
- 重复运行和跨环境复现；
- 真实应用案例或误差分析；
- 理论结果与实际测量的差异解释。

只有 rubric、任务书或教师说明支持时才计入可恢复分数。额外实验仍须预注册问题、正确性门槛、raw schema、失败程序和结论边界；不能为“看起来丰富”制造没有问题意识的图表。

## 11. 从实践发现并解决问题

实验不是一次性证明预设答案。使用：

```text
pilot/运行 → 观察漂移、失败、异常或限制 → 复现
→ 区分实现、协议、数据和环境根因 → 修复
→ 重跑相同门槛 → 比较前后 → 形成下一问题
```

保留失败运行及协议变更记录。实践中发现的新问题可以进入下一轮，但必须先判断它是否影响官方评分、证据有效性或只是内部质量机会。

## 12. 数据图与结构图分工

折线、条形、箱线、散点和热力图必须从正式数据生成。架构、流程、机制、状态机和组件交互图不是数据图，可按 [05-document-and-presentation.md](05-document-and-presentation.md) 使用 `$figgenie-paper-diagram`。图形选择发生在采集数据前，避免实验结束后才发现缺少必要指标。
